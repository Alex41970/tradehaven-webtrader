# Architecture rules

- Buyer releases use the opt-in locked Vite mode with an offline exact-host entry gate, obfuscated chunks and explicit buyer-owned public connection settings; normal builds stay unchanged and no seller licensing endpoint is introduced.

- Import the database client from `@/integrations/supabase/client` and use the generated `types.ts`; never hand-edit generated connection or type files.
- Server-trusted money changes (balances, margins, trade settlement) happen inside SECURITY DEFINER database functions; the `prevent_user_financial_updates` trigger blocks only direct edits made as the `authenticated` role, so keep it SECURITY INVOKER.
- Account figures have one source: the `validate_user_balance` trigger derives `used_margin`, `equity` (balance + credit + open P&L) and `available_margin` on every `user_profiles` write; code never sets them, it only touches the row. `src/utils/accountMetrics.ts` mirrors the formulas (vitest) — keep both identical.
- Credit (company money, tradable, never withdrawable) changes only through `admin_modify_user_credit` and `settle_account` (flat account + negative balance -> credit covers it, then the negative-balance setting); every change writes a `credit_transactions` row. Withdrawals are limited by `account_withdrawable` (credit excluded) on request and again on approval — never compare against free margin.
- Direct API writes are guarded by SECURITY INVOKER triggers (`guard_trade_changes`, `guard_money_requests`, `guard_trade_order_changes`): clients may only open a market trade, edit SL/TP, and file pending requests/orders; balance and credit are frozen for everyone on direct edits. Functions running with the service role (e.g. `websocket-trading-updates`) bypass these, so they must check trade ownership themselves and never pass client-supplied `parent_order_id`.
- Sign-up is invite-only via admin promo codes; `signup_requires_promo()` relaxes this only while no admin exists (first-run bootstrap). Social sign-in is deliberately not offered because it would bypass promo codes.
- Scheduled server work uses managed HTTP schedules with `authenticateCronRequest`; never embed keys or backend URLs in SQL.
- Prices: the scheduled `price-feed` function is the single price source (free providers first, paid fallback capped per run; each run fetches in several passes and every provider stays at or below 70% of its limit); it writes `assets` + `price_candles` and runs `process_price_triggers()` (SL/TP, margin call, stop-out). Clients poll `assets` and only simulate small, bounded moves around the real price; never let client-simulated prices drive execution.
- P&L and margin are lot-based (`calc_trade_pnl` in SQL, `src/utils/pnlCalculator.ts` in the client); keep both formulas identical. The `trades` insert trigger is the authority for open price and margin.
- Charts are built in-app from `price_candles` (lightweight-charts); don't reintroduce third-party chart feeds that use different prices.
- Price feed health: every `price-feed` run logs to `price_feed_runs` (provider calls incl. fallback retries, errors, blocked outlier jumps); `ingest_prices_v2` rejects outlier jumps and sets `price_changed_at` only on real moves; clients don't simulate movement on markets whose real price hasn't moved for 30 min. Admins see it in the Price Feed tab via `get_market_health()`.
- Signed-in pages use `src/components/layout/AppShell` (sidebar + top bar + phone tab bar) and `src/components/dashboard/widgets` (bento cards, Recharts); colors only via theme tokens in `src/index.css` — keeps one consistent frame and theme.
- Market intelligence (sentiment, price alerts, watchlists, journal) lives in `src/components/intel` + `src/utils/marketIntel.ts` (unit-tested with vitest); alerts trigger only on `serverPrices` from PriceContext, never simulated prices, and sentiment only claims "trader" numbers when `get_market_sentiment` returns real positions (5+ traders).
- Phones (<768px) get their own trade flow inside `WebTrader` (market list -> chart with pinned one-tap Buy/Sell bar -> order sheet) and AppShell shows 4 tabs + a "More" sheet; dialogs become bottom sheets via `ui/dialog`. Keeps every action reachable on phones without a separate mobile app.
- Market hours live in `src/utils/marketHours.ts` and SQL `is_market_open()` (keep identical, vitest-covered); closed markets accept only pending orders (`trade_orders`), filled server-side by `fill_pending_orders()` inside `process_price_triggers()`, and the `trades` insert trigger refuses instant trades while closed (admins exempt).
- Client account state (profile, trades, live-link status) lives in one shared store: `src/services/accountStore.ts` (pure, vitest-covered) driven by `src/services/account.ts` and read through `src/hooks/useAccount.ts`; hooks such as `useTrades`/`useSharedUserProfile` are thin readers and must not hold their own copies or polling. Equity, P&L and margin on screen are derived from the store's open trades on every render, never stored — separate copies let a closed trade keep moving equity.

- Fresh-backend setup SQL (`deploy/setup_db.sql`) is generated by `deploy/build_setup_sql.py` from `drizzle/migrations` + `deploy/assets.csv` and resets the public schema inside one transaction; the old `supabase/migrations` chain is not replayable, so never concatenate it.
